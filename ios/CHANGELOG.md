# iOS App 更新日志

本文件只记录 TelePilot iOS App 自身的变化，遵循 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/) 与 [SemVer](https://semver.org/lang/zh-CN/)。iOS App 版本号独立于 TelePilot 服务器版本，规则见仓库根目录 `AGENTS.md`「iOS 版本」。

- **MINOR（0.X.0）**：用户可感知的新能力、页面或信息架构重组、重要工作流变化。
- **PATCH（0.X.Y）**：bug 修复、文案、小 UI 与兼容性调整。
- 版本号只在 iOS 发版检查点 bump；开发中的改动先记入 `Unreleased`。build 号由 CI 打包时生成，不写在这里。
- 每个版本段落的标题格式为 `## [版本] - 日期 · 级别 · 主题`，下一行用 `> 对应服务器：…` 注明随哪个服务器检查点或 Beta 合并发布。本文件随 App 打包，在“关于 → App 更新日志”中离线显示，请保持该格式。

## [0.24.0] - 2026-10-30 · minor（次版本） · 交互页补齐「测试模拟通知 Bot」与转账结果通知 Bot 配置

> 对应服务器：随 Beta 合并发布（不需要新服务器，使用已有的交互配置接口；旧服务器没有测试模拟字段时这一组自动隐藏，查看已保存 Token 需要 0.113.0-beta.5 起）

### 新增

- 交互页新增「测试模拟通知 Bot」一组，和 Web 管理台「身份配置」右栏一致：填写或查看「测试模拟通知 Bot Token」（小黑点遮罩，点眼睛先验证 Face ID / 密码再从服务器读取）、看到服务器识别出的当前测试 Bot ID、清除已保存的测试 Token；「模拟测试群」用原生勾选列表从会话白名单里多选，也可以手填 Chat ID（一行一个），不在白名单里的 ID 单独列出、点一下即可移除；「测试 Bot 群成员状态」显示测试 Bot 是否已进这些群。只有明确选中的群会响应 +金额、-金额模拟命令，留空不启用任何测试群。
- 「清空通知 Bot」：一键清空真实通知 Bot ID 和测试 Token（确认后点「保存」生效，模拟测试群保留）。

### 改进

- 「可信通知 Bot ID」从“高级”页挪到交互页，改名「真实转账结果通知 Bot」，说明写清楚填什么；“高级”入口改名「查询指令与通知模板」。
- 交互 Bot 的入群情况改名「监听群成员状态」，放进「交互总闸与 Bot」分组；状态拿不到时显示「无法确认」（与 Web 一致）。
- 规则列表：规则多于一条时顶部可按「全部 / 启用 / 暂停」筛选；长按规则可上移、下移、复制（名称加“副本”，玩法参数一并复制）、停用或删除，和 Web 规则列表的按钮对应。

## [0.22.0] - 2026-10-30 · minor（次版本） · Telegram 消息格式预览：边写边看气泡效果

> 对应服务器：随 Beta 合并发布（不需要新服务器；模板实验室使用已有的模板目录、渲染与测试发送接口）

### 新增

- 写消息模板时实时看到 Telegram 里的样子：仿 Telegram 聊天气泡（Bot 名、时间、浅色／深色），粗体、斜体、下划线、删除线、行内代码、代码块（显示语言名，可一键复制）、链接、引用、可折叠引用（点“展开”看全部）、隐藏文字（灰色块，点一下揭开）、自定义表情（显示替代表情）都按 Telegram 的效果显示；富文本消息的标题、列表、表格、勾选框等也能预览。解析规则与 Web 管理台的预览完全一致。
- 比 Web 多做了几件事：边输入边更新预览；显示已用字数和上限（普通消息 4096、带图片的说明文字 1024），接近上限变橙、超出变红并说明 Telegram 会拒绝；标签没闭合、交叉嵌套、多余的结束标签、Telegram 不支持的标签、没转义的“<”“&”都会用中文提示，并写明第几行第几列、标出那一段；模板里的变量（如 {name}）用示例值代入并以浅色底标出，没有示例值的变量用橙色底提醒，示例值可以自己改着看效果；点“展开编辑”可切换「分屏 / 编辑 / 预览」和预览外观。
- 「指令与任务」新增原生的「消息模板实验室」（替换原来的三个原始表单）：选账号后按分组列出插件与系统消息模板，打开即可编辑、预览和检查格式；再一键交给服务器渲染校验，校验通过后可向授权用户测试发送（发送前确认，不自动重试）。服务器模板带内联按钮时，气泡下方也会显示按钮。

### 改进

- 这些地方的模板输入框下方都直接显示预览、字数与格式提示：插件配置里的模板字段（名字以 _template 结尾的字段，插件声明了预览字段时，配置页还会按顺序显示一组消息气泡）、AI 指令的输出模板（含条件块，留空时预览默认格式）、回复文本指令、交互 Bot 的玩法查询模板（回复模板 + 条目模板组合成整条消息预览）、收款／扣款通知模板、交互规则的命中回复。

## [0.19.0] - 2026-10-30 · minor（次版本） · 插件页「运行树」：运行模式、模块开关与插件接入方式

> 对应服务器：随 Beta 合并发布；TelePilot 0.113.0-beta.2 起按账号口径返回运行树（插件中文名、真实接入方式、关不掉的原因），连接旧服务器时 App 自己按账号计算，照常显示

### 新增

- 插件页（插件中心）加「插件 | 运行」切换，和 Web 插件页的「卡片视图 | 树状视图」对应；账号选择沿用插件页上方那个。「运行」视图叫「运行树」，回答“这台服务器开了哪些模块、哪些插件在用”，从上到下：
  - **运行模式**：当前是生产还是值守、账号进程在线数、紧急停止状态。点「进入值守…」先预演，确认框列出会关掉哪些模块（以及值守期间交互 Bot 的观测盲区）；值守中显示「恢复生产」，逐项还原进入前的状态。
  - **可选模块**（AI、交互 Bot、入站 Webhook、资金台账、命中调试）：每行有运行状态、「被 N 个插件需要」和开关。被插件需要时开关不可用，并写明是哪些插件、在哪些账号；值守中关掉的模块写明“恢复生产后才会重新打开”。没人需要的可以直接关，开关前有确认框。点模块查看需要它的插件，再点进插件配置。
  - **插件按接入方式分组**：「直通（最先处理）」「主通道」「交互 Bot」三组；每个插件显示是否在本账号启用、靠什么工作（命令、事件订阅、定时任务……）、额外需要的模块、需要的模块没开导致起不来的提示与最近的运行异常。点插件进入这个账号里的插件配置；交互插件旁的「交互规则 ›」跳到交互中心。
  - 底部「想看一条消息怎么走 → 命中调试」。

### 改进

- 和 0.18.0 的模块联动一致：服务器关闭「命中调试」时运行树底部不显示命中调试链接，关闭「交互 Bot」时插件旁不显示「交互规则 ›」；在运行树里开关模块、进入值守或恢复生产后，Dock 与「更多」里的入口立刻跟着显示或隐藏。
- 「服务器设置」里的「能力与插件树」和「平台运行模式」原始文档入口删除，改为一行「运行树与运行模式（已移到 插件 › 运行）」，点按直接打开新位置。

## [0.18.0] - 2026-10-30 · minor（次版本） · Dock 改造：交互进 Dock、自定义 Dock、按模块开关隐藏入口、插件与交互互相跳转

> 对应服务器：随 Beta 合并发布（不需要新服务器：模块开关读取已有的 `/api/system/capabilities`；旧服务器没有模块信息时所有入口照常显示）

### 改进

- 底部 Dock 默认改为“概览 · 插件 · 交互 · 更多”，右侧仍是 Agent。交互中心从“更多 › 管理”第 3 层挪到 Dock，点一下就能看交互 Bot 是否在跑、改规则；页面标题也叫“交互”。
- AI 挪进“更多”：“更多”按“常用 / 管理 / 工具与设置 / App”分组——管理里是账号、AI、指令与任务、资金台账、日志；工具与设置里是 Webhook、服务器设置、备份与维护；App 里是 App 设置、关于与更新。已经放进 Dock 的入口不在“更多”里重复出现，从 Dock 移出的入口自动回到“更多”。

### 新增

- “App 设置 › 自定义 Dock”：Dock 中间最多 3 格，可以从概览、插件、交互、AI、指令与任务、账号、日志、资金台账里选择并调整顺序（“更多”和 Agent 固定）；至少保留一格，可一键恢复默认。只保存在这台设备上。最多 3 格是因为 iPhone 底部超过 4 个普通标签时系统会再生成一个“更多”。
- 服务器关闭了某个模块时，对应入口自动隐藏，和 Web 管理台一致：交互、资金台账、Webhook、AI、命中调试（日志与诊断里的“模拟消息路由”“投递统计”“开启路由诊断记录”）。Dock 里被隐藏的那一格由下一个入口补上（默认是 AI）；模块重新开启后自动恢复。
- 插件和交互互相跳转：交互类插件的详情页多了“交互规则 ›”，打开交互中心并只列出启动这个插件的规则（可切换显示全部，新加的规则直接指向这个插件）；交互规则编辑页选了插件玩法后，多了“插件配置 ›”，直接打开该插件在这个账号的配置。

## [0.17.0] - 2026-10-30 · minor（次版本） · 原生插件市场、全部更新改为并行

> 对应服务器：TelePilot 0.113.0-beta.1（插件市场接口）；连接旧服务器时市场页提示更新服务器，其它插件功能不受影响

### 新增

- “插件 › 发现”顶部新增“插件市场”入口（有可更新插件时显示数量），和 Web 管理台的插件市场页使用同一组接口：浏览官方源与自定义来源里的插件（图标、名称、信任等级、类型、简介、版本、已安装版本），搜索、按类型筛选、只看可更新；没装的点“获取”安装，有新版本的点“更新”；“全部更新”一次更新所有有新版本、没有固定版本的插件，服务器同时更新几个（数量见“更新参数”），单个失败不影响其它，结果逐个列出。
- 插件详情：版本、最低服务器版本、需要的权限；可以“固定版本”，固定后全部更新与自动更新都会跳过它。
- 更新后的健康观察：正在观察的更新可以“确认正常”或“立即回滚”；服务器自动回滚过的插件会显示回滚原因。
- “来源管理”：启用 / 停用官方源，打开或关闭官方源的自动更新（默认关闭）；添加自定义来源（registry.json 的 https 地址、名称、信任等级），删除自定义来源。
- “更新参数”：同时更新数量（1–8，默认 3）与更新后观察时长（3–60 分钟，默认 10）。

### 改进

- “已安装 › 全部更新”从一个个按顺序更新改为同时更新多个（数量取服务器的“同时更新数量”，旧服务器为 3）；某个插件失败不影响其它，网络中断导致结果未知时不再开始新的更新。

## [0.11.0] - 2026-10-26 · minor（次版本） · Cloudflare Access：App 内 Google 验证

> 对应服务器：0.106.0-beta.6

### 新增

- 支持服务器前套了 Cloudflare Tunnel + Access（Allow 策略 = 邮箱白名单 + Google 登录）的部署，**Cloudflare 后台无需任何修改**：登录页「Cloudflare Access（可选）」区和 设置 → Cloudflare Access 新增「使用 Google 验证」。App 照搬官方 `cloudflared access login` 流程：用系统登录窗（Google 不允许 App 内嵌网页登录）打开服务器的 Access 登录页，同时轮询 Cloudflare 令牌转交服务，取回用本机一次性密钥加密的 Access 登录令牌后自动关闭窗口。
- 令牌只保存在本机钥匙串、按服务器分别保存、不同步 iCloud、不写日志；之后 App 的所有请求（登录、读取、写操作、下载上传、助手实时输出、推送注册等）都带 `cf-access-token` 请求头。界面显示 Access 会话的账号邮箱与到期时间，可随时「移除 Access 登录」。
- 「高级：Service Token」保留为可选项（需要在 Access 应用里另加一条 Action 为 Service Auth 的策略）；填写后只带 `CF-Access-Client-Id` / `CF-Access-Client-Secret`，清除后自动改回 Google 验证。
- App 内「Cloudflare Access 使用说明」：Google 验证步骤、到期处理、Binding Cookie 注意事项与 Service Token 后台配置。

### 改进

- 被 Cloudflare Access 拦截时不再笼统显示「服务器返回了重定向」：按情况提示「请先用 Google 完成 Access 验证」「Access 登录已过期」「Access 不再接受当前的登录」或「Service Token 被拒绝」。登录页在 Access 区显示引导；已登录时（会话过期或请求被 302 到 `*.cloudflareaccess.com`）直接弹出 Access 页面，一键重新验证，验证后自动关闭并刷新数据。
- Access 拦截发生在 Cloudflare 边缘，不会被当成登录失效而清除 TelePilot 会话；写操作被拦截时明确是「未执行」，重新验证后不会自动重新提交。其他重定向仍按原安全规则拒绝。
- 启动时恢复会话被 Access 拦截：在登录页完成 Google 验证后自动用原会话只读重试，无需重新输入密码。
- 「更换服务器」会一并移除这台服务器的 Access 登录令牌与 Service Token。

- 首个 iOS 原生客户端：复用服务器 Cookie 与 CSRF 登录，提供健康概览、账号列表与详情、暂停与恢复，并可在浏览器打开完整管理台。
- 完整管理能力：账号自动化、插件与规则、指令任务、AI 与系统助手、日志诊断、资金台账、Webhook、系统维护等原生入口；Face ID 解锁、隐私遮盖、全局搜索、收藏、可定制首页、iPad 双栏布局和原生文件导入导出。
- 可选 APNs 推送：助手待确认、任务完成和运行异常通知，通知不携带认证凭据或业务敏感正文。
- 原生 Liquid Glass 底栏，固定为“概览、插件、AI、更多”，iOS 27 上使用原生圆形 Agent 入口；插件与 AI 工作流按账号与用途分段。
